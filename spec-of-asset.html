01 资源管理综述 分类 · 路径 · 命名
1.1 资源分类分类维度
🎯 三种分类维度
按类型分类
主要按文件格式和功能用途分类：图片资源、音频资源、视频资源等
按应用分类
主要按资源的应用场景分类：场景资源、图标等
按分工分类
主要按美术制作分工分类：原画资源、Spine 资源、场景资源等
📦 项目使用资源类型和应用场景混合分类（8 大类）
资源大类英文章节名说明
角色资源Character用于游戏内角色展示的所有资源，含静态展示（头像）和动态展示（动作）。涉及：角色原画、角色动画、静态切图。具体含剧情立绘 / Q版 / 玩家换装
场景资源Map游戏内场景类资源，主场景构建资源，及场景功能相关的动态、替换类资源。由场景原画设计、动画人员补充动特效
图标资源Icon游戏内最主要的配置型静态资源，主要以 2D Sprite 形式使用。可分为：附带型（如角色头像、种植物图标）+ 独立型（如物品图标、功能图标）
动特效资源Effect游戏内动画类资源，独立动特效目录。狭义动特效主要以 Spine 制作输出；界面动效以 Animation 为主（属于界面资源）；固定关联于角色/场景的特效属于对应资源
音视频资源Media音视频类资源，基于游戏内其他资源配套设计（基于场景的 Bgm / 基于动特效的 Audio / 基于剧情台词的 CV 等）
美宣资源Poster非游戏内实装，用于平台（五图、分享图等）和/或运营宣发用途的素材；外包核算分类中游戏内大型插画等也属于此
界面资源UIRes游戏交互界面的静态素材、字体、界面动效。相较其他美术资源，逻辑关联性、规则性要求更高
资源流程—贯穿各资源类型的需求 / 制作 / 验收 / 提交 / 发布 / 归档全流程规范
📌 特别注意：界面动效属于界面资源；与角色/场景固定关联的特效属于对应资源；通用逻辑调用的界面/角色/场景特效都属于独立动特效。
1.2 资源路径四库体系
① 美术 SVN 资产库
由美术管理维护，收录美术日常制作资产 + 各时期确认使用的资源独立归档。
https://svnshh.dobest.com/svn/anthea_art
/2D 场景 /2D 动效 /2D 角色 /UI /归档
归档目录：源文件 + 预览文件，按需求分类作为一级目录（如【1. 角色】【2. 场景】）
② 项目 SVN 资源库
以输出提交为主要用途，兼顾美术资产库和工程资源库的对应。
https://svnshh.dobest.com/svn/anthea/art
/1. 游戏角色 /2. 游戏场景 /3. 图标图素 /4. 动画特效 /5. 媒体音频 /6. 美宣素材
命名风格：中英文对照 + 数字序号保证排序
③ FGUI 工程资源库
项目使用 FGUI 进行界面及花艺品编辑，由交互设计 + 资源策划管理维护的工程。
https://svnshh.dobest.com/svn/anthea/client/FGUI
/Anthea_GUI/assets /Anthea_Floral/assets
目录 & 文件纯英文命名（除预览效果图）；FGUI 预制组件（xml）也需严格命名
④ trunk 工程资源库
由资源策划管理维护的工程 SVN 资源库，为项目工程直接使用的资源路径。
https://svnshh.dobest.com/svn/anthea/client/trunk/assets/resources
/Character /Map /Icon /Effect /fgui /Floral /Story
目录分类偏向应用场景而非需求分类；纯英文命名；含程序可调用预制体
📌 四库对应关系：美术 SVN 资产库（日常归档）→ 项目 SVN 资源库（中转核对）→ FGUI/trunk 工程资源库（直接进包）。
同一资源在三个库中均有存放，路径可明确对应。
1.3 资源命名三段式
📁 1.3.1 文件夹命名
  • 文件夹深度不超过 3 层
  • 拆分标准：目标对象的分类/分组，以及单个具体对象有多个文件
  • 示例：../1. 角色 - Character/$角色名 - $RoleName/Q 版 - Avatar/
资产库命名规则
美术 SVN 资产库以日常工作为主要用途，文件夹命名以中文为主；日常目录以工种划分（如【2D 角色】【2D 场景】）；资产归档以需求分类为一级目录
项目 SVN 资产库以输出提交为主要用途，命名以中英文对照为主；一级目录基本对照【美术资产库/归档目录】（如【1. 角色 - Character】【2. 场景 - Map】）
工程 SVN 资产库（FGUI/trunk）用于工程内直接调用，文件夹以纯字母命名，不使用数字序号排序（自带数字可保留）
📐 1.3.2 文件命名通则
通用形式：$CLASS_$ResName_$standard
分段属性格式
$CLASS非必要 · 前缀全大写、字母（英文单词或缩写，≤3 个字母）。命名中分类指设计、规格、应用不同的同目录、同文件类型的不同资源
$ResName必要 · 本体大驼峰、字母 + 数字（≤3 个拼音/单词 + 2 位数字）。资源动态匹配时对应配置中「资源标识 res」的本体文件名。尽可能使用拼音命名
$standard非必要 · 后缀全小写、字母 + 数字（≤1 个拼音/单词 + 2 位数字）。区分不同应用场景、状态。尽可能使用英文单词，避免任意新增
📋 1.3.3 文件命名适用
资产库命名要求
美术 SVN 资产库以制作源文件、预览文件为主，不会直接进包，日常人工查找使用为主。命名以中文为主，无需严格遵循通则，但仍需满足：简洁、概括、可区分
项目 SVN 资源库制作内容导出中转，应按进包要求的规格、样式、命名提交。资源策划会进行验收、核对和修改，再正式导入工程
工程 SVN 资产库（FGUI/trunk）除少量代图、效果图外，全部属于进包资源，直接用于游戏运行和展示。务必严格遵守进包规格、样式、命名规范；引擎内拼制的资源预制体文件同样必须遵守

05 动特效资源 Effect Spine · 序列帧 · 程序动画
5.1 动特效分类分类
5.1.1 按制作方式
  • Spine 动画：基于 2D 骨骼绑定与蒙皮
  • 序列帧动画：连续播放静态帧（视觉暂留）
  • 程序 Animation：引擎 + 代码实现
5.1.2 按应用分类
  • 界面动特效：界面交互、状态、事件触发
  • 角色特效：角色动作、状态触发；固定关联特效可与角色动作一并制作
  • 场景特效：场景元素动画、状态、事件触发；固定关联特效可与场景物件一并制作

06 音视频资源 Media BGM · Audio · CV · Video（V260429 更新重点）
6.1 分类说明4 类
游戏内音视频资源，通常为独立外包设计制作，有专属需求沟通和反馈过程。
🎵 6.1.1 背景音乐 Bgm
  • 匹配不同游戏功能场景（主场景 Bgm、剧情 Bgm 等）
  • 时长 ≤60s；输出比特率 128kbps
  • 输出格式：.mp3（避免 wav 体积过大）
🔊 6.1.2 音效资源 Audio
  • 时长 ≤3s；输出比特率 128kbps
  • 分类：界面 / 角色 / 特效 / 独立音效
🎤 6.1.3 语音资源 CV
  • 与角色塑造相关，对应特定场景台词
  • 输出比特率 128kbps，格式 .mp3
  • 分类：界面语音 / 动效语音 / 口头禅 / 剧情语音
🎬 6.1.4 视频资源 Video
  • 特殊剧情 / 动画表现形式（PV、CG 等）
  • 输出格式：.mp4（确保多设备播放支持）

09 资源流程规范 需求 → 会议 → 制作 → 验收 → 提交 → 发布 → 归档
🔄 全流程主干（6 阶段）
9.1 流程
① 资源需求
会议规范

9.1.1 资源需求
资源策划 → 系统策划 → 文案/交互 → 资源策划 → 美术
  • 【资源策划】美术周会后反馈需求补充；评估存量并提出下周增补
  • 【系统策划/文案策划】当天完成，最晚不迟于美术开工
  • 【文案/交互策划】最迟周三下班前交付资源策划
  • 需求中须明确：资源分类、命名、输出标准 & 规格、提交路径
9.1.2 会议规范
  • 分单双周：版本内容 vs 常规铺量（由资源策划发起）
  • 会前：文案策划提前完成需求文档，资源策划核对后协调时间
  • 参会：版本内容会 — 制作人+文案+资源策划+美术全员+PM/APM
  • 常规铺量会：制作人+文案+资源策划+相关制作人员+PM/APM
  • 会议形式：文案主持讲解 → 美术提问 → PM/APM 分工排期 → 资源策划落地 Jira 子任务
9.1.3 资源制作
组长/APM → 执行美术 → 外包制作 → 日常提交
  • 业务组长/主美指导分析，APM 确认排期
  • 执行美术自制作或推进外包
  • 参照美术 SVN 分类日常目录提交规则执行；外包需必要约束和规则说明
9.1.4 资源验收
组长/文案 → 资源策划 → 系统策划
  • 组长/文案验收：确认提交内容、数量的准确性
  • 资源策划验收：确认路径、命名、规格的准确性
  • 系统策划验收：确认内容、适用、数量的准确性
9.1.5 资源提交
执行美术 → 资源输出
  • 制作完成且需求方确认效果后，由美术执行人员提交输出至项目 SVN 资源库
  • 输出时核对：分类、命名、输出标准 & 规格、提交路径
9.1.6 资源发布
资源策划 → 系统策划 → 客户端程序
  • 资源策划核对后将导出资源迁入工程 SVN 资源库，进行必要拼制
  • 提交系统策划最终验收展示效果
  • 提交客户端程序实装应用
9.2 资源归档3 类
9.2.1 源文件归档
  • 执行美术提交至美术 SVN 资产库归档目录
  • 包含：制作源文件 + 效果预览图/视频
  • 资源策划定期核对检查
9.2.2 资产库备份
  • 美术资产库已通过 SVN 管理，日常无需人工备份
  • 重大改版前预期资源复用度低时，针对整个资产库备份
  • 命名格式：_backup + 年月（如 _backup2022.12）
9.2.3 资源库备份
  • 工程资源库：永远保留当前版本实际应用资源，不保留历史资源，不涉及备份
  • 项目资源库：日常通过 SVN 历史版本管理即可；重大版本节点可备份
  • 命名：_backup/art_1.3.5 = ver1.3.5 版本美术资源备份
