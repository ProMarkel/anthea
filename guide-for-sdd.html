🎮Cocos CreatorSDD + Claude Code + OpenSpec  AI Coding 工作流搭建清单

适用于游戏项目团队，按 Tech Lead / Design Lead / 程序员 / 策划设计 / 测试QA 五类角色分工

阶段1 环境准备 1-2天 阶段2 规范制定 2-3天 阶段3 AI工作流 持续迭代 生成时间：2026-06-05
阶段 1 环境准备与基础工具链 预计 1-2 天
1
统一开发工具版本
Node.js LTS · Cocos Creator · TypeScript 配置
全员 Tech Lead 主导
›

🆕 引入 MCP 工具服务
为 Claude Code 接入外部工具能力（Git · 文件系统 · 自定义）
Tech Lead 主导 新增
›
MCP（Model Context Protocol）允许 Claude Code 调用外部工具。本节按三档优先级列出适合 Cocos Creator 游戏项目的 MCP 服务，建议在环境准备阶段完成核心服务的配置。
第一档 · 核心必备（全员配置）
T1 Cocos Creator MCP Server
GitHub: DaxianLee/cocos-mcp-server（1k+ Star）— 让 Claude Code 直接操控 Cocos Creator 编辑器。
场景操作：打开/保存场景、获取完整层级（含组件信息）
节点操作：创建/删除/移动/改属性、预制体实例化
组件操作：添加/删除内置组件、挂载自定义脚本
资源管理：批量导入/删除/移动、获取依赖关系
项目控制：运行/构建项目、检查构建状态
调试工具：获取控制台日志、验证场景完整性
// 安装：将插件复制到项目 extensions/cocos-mcp-server/ // 在 Cocos Creator 扩展管理器中启用后，Claude Code 侧配置： { "mcpServers": { "cocos-creator": { "type": "http", "url": "http://127.0.0.1:3000/mcp" } } }
T1 Figma MCP（官方远程版）— Design Lead 核心工具
打通 Figma 设计稿 → Claude Code，AI 直接读取图层结构、Design Token、Auto Layout 生成 UI 代码。
读取设计上下文：组件 / Variables / 布局数据

第二档 · 强烈推荐（按角色配置）
T2 Context7 MCP
从源码仓库拉取实时 Cocos Creator API 文档，避免 Claude 输出过时 API 用法（如 cc.tween 版本差异）。
T2 Memory MCP（知识图谱版）
跨会话持久记忆。反复调整同一系统时（花圃经营 / 心之露 / NPC 好感度），AI 不会忘记上一次对话的决策和踩过的坑。

T2 FairyGUI MCP — Design Lead / 程序员 核心工具
GitHub: kaohum/FairyGUI-MCP（MIT）— 让 AI 直接控制 FairyGUI 编辑器，27 个工具覆盖组件浏览/打开/截图验证/控制器切换/发布全流程。

控制器：列出/切换控制器页面（验证按钮状态）
发布：发布单包/全包（与 Cocos 构建集成）

MCP 安全注意事项
1. resources/ 目录建议在 MCP filesystem 配置中设为只读，防止 AI 误修改美术资产
2. CI 环境下的 Claude Code 应使用独立的 allowedTools 配置，只给只读权限
3. Cocos Creator MCP 的运行前提：Cocos Editor 必须保持打开状态
  • 在 .claude/settings.json 中按角色模板配置 MCP 服务器列表
  • Tech Lead 确认 Cocos Creator MCP 插件已安装并配置（Editor 扩展管理器 + http endpoint）
  • Design Lead 确认 Figma MCP 可用：claude plugin install figma@claude-plugins-official
  • 验证各 MCP 工具连接正常：在 Claude Code 中测试读取文件、查询 Git diff、读取 Cocos 场景
  • 在 CLAUDE.md 中写入 MCP 工具用途说明和 allowedTools 使用约定
  • 配置 resources/ 目录的文件只读权限（MCP filesystem 白名单排除）

编写 CLAUDE.md — 项目约束文件
架构约定 · 命名规范 · Cocos 特有规则 · 禁止操作
Tech Lead 主导 程序员参与
›
CLAUDE.md 是 Claude Code 每次启动时自动读取的约束文件，等同于给 AI 的「项目规则书」。内容越具体，AI 生成的代码越符合团队规范。
必须包含的章节
  • 项目概述：游戏类型、引擎版本、技术栈（TypeScript + Cocos 3.x）
  • 目录结构说明：哪些目录 AI 可以读写，哪些禁止修改（如 build/ settings/）
  • 命名规范：组件类 PascalCase，属性 camelCase，资源路径 kebab-case
  • Cocos Creator 特有约束（详见下方示例）
  • MCP 工具使用约定：filesystem 只能读写 spec/ 和 scripts/，禁止操作 resources/ 二进制资产
  • 代码风格：async/await 优先，禁止裸 Promise chain；错误必须 catch 并 log
  • AI 禁止操作：不得修改 project.json，不得直接写入 .meta 文件
Cocos Creator 特有约束示例
## Cocos Creator 特有约束 ### 组件编写 - 所有组件必须继承 Component，使用 @ccclass 和 @property 装饰器 - @property 必须显式声明 type，禁止使用裸 @property() - 节点引用优先用 @property(Node)，禁止 find() 字符串查找（运行时易断裂） - 禁止在 update() 中进行资源加载或实例化 ### 生命周期 - onLoad：初始化变量，绑定事件监听 - start：处理依赖其他组件初始化后的逻辑 - onDestroy：必须解绑所有事件，清理定时器 - 禁止在 constructor 中访问 this.node ### 资源加载 - 动态加载统一使用 resources.load()，路径相对于 resources/ 目录 - 预制体必须通过 @property(Prefab) 引用，禁止硬编码路径字符串 - resources.load 必须处理 error 回调 ### 事件系统 - 全局事件用 EventTarget 单例，禁止直接 node.emit 跨组件通信 - 事件名必须定义为常量枚举（EventNames.FLOWER_PICKED）

编写 OpenSpec Spec 文档模板
proposal.md · design.md · tasks.md 三件套
Tech Lead 策划参与 Design Lead 参与 程序员参与
›
每个功能模块对应一套三件套文档。proposal 由策划/PM 主导，design 由程序员主导，tasks 由 Tech Lead + 程序员共同拆解。
proposal.md — 需求意图文档
# [SPEC-001] 花圃种植系统 ## 背景与目标 玩家核心循环的起点：种植花卉 → 产出心之露 → 解锁剧情。 目标：让玩家在3步内完成第一次种植体验。 ## 用户故事 - 作为玩家，我可以点击空地格子选择花种 - 作为玩家，我可以查看每朵花的成长进度 - 作为玩家，花朵成熟时我会收到通知并可收获 ## 功能边界（In Scope） - 6格花圃，支持不同花种 - 成长阶段：种子 → 幼苗 → 开花（3个视觉状态） - 收获时产出心之露（数值由策划表配置） ## 不做的事（Out of Scope） - 本版本不做浇水/施肥机制（v2 迭代） - 不做花圃扩建功能 ## 验收标准 - [ ] 空格点击弹出花种选择面板 - [ ] 倒计时成长，时间配置在 GameConfig.ts - [ ] 收获动画播放完成后心之露数值+X
design.md — 技术设计文档
# [SPEC-001] 技术设计方案 ## 模块架构 FlowerGardenManager (单例) ├── FlowerSlot[] (6个格子组件) ├── FlowerDataConfig (配置表，ScriptableObject) └── FlowerEventBus (事件中枢) ## 数据结构 interface FlowerSlotData { slotId: number; flowerType: FlowerType | null; plantedAt: number; // Unix timestamp stage: GrowthStage; // SEED | SPROUT | BLOOM } ## 关键接口 - FlowerGardenManager.plant(slotId, flowerType): void - FlowerGardenManager.harvest(slotId): HeartDewReward - FlowerSlot.updateVisual(stage: GrowthStage): void ## 持久化方案 存入 sys.localStorage，key: "flowerSlots" 游戏启动时 onLoad 读取并恢复状态 ## 依赖关系 依赖：HeartDewManager（产出结算） 被依赖：QuestSystem（任务触发）
tasks.md — 开发任务拆解
# [SPEC-001] 开发任务列表 ## Sprint 任务 ### T1 · 数据层 (0.5d) - [ ] 创建 FlowerType 枚举和 FlowerConfig 配置表 - [ ] 实现 FlowerSlotData 接口和本地持久化逻辑 - [ ] 单测：存储/读取/重置逻辑 ### T2 · 组件层 (1d) - [ ] FlowerSlot 组件：点击 → 选种面板 → 种植 - [ ] FlowerSlot 视觉状态切换（3个 Sprite 帧） - [ ] FlowerGardenManager 单例及生命周期管理 ### T3 · 成长系统 (0.5d) - [ ] 基于 schedule() 的成长定时器 - [ ] 成熟通知（EventBus → UI 层徽章） ### T4 · 收获结算 (0.5d) - [ ] 收获动画 → HeartDewManager.add(amount) - [ ] 联调：触发 QuestSystem 事件 ## Claude Code 辅助提示词 在 tasks.md 同目录下放置 prompt.md，内容： "参考 design.md 的接口设计，实现 T2 FlowerSlot 组件。 遵循 CLAUDE.md 中的 Cocos Creator 约束， 使用 @ccclass @property 装饰器， onDestroy 中解绑所有事件。"

🆕 引入 Claude Code Skill（自定义命令）
封装项目专属 Slash Command，提升复用效率
Tech Lead 程序员 新增
›
Claude Code 支持在 .claude/commands/ 目录下定义项目级 Skill（Slash Command）。将常用 prompt 模板封装为命令，团队成员输入 /spec-gen 或 /cocos-review 即可一键触发。
  • 建立 .claude/commands/ 目录
  • 创建 spec-gen.md：输入需求描述，自动生成 proposal.md + design.md 草稿
  • 创建 cocos-review.md：对当前文件进行 Cocos Creator 规范审查，输出 checklist
  • 创建 task-impl.md：读取 tasks.md 中指定任务，按 design.md 接口生成实现代码
  • 创建 fix-lint.md：读取 ESLint 报错，自动生成修复方案（对接 CI）
# .claude/commands/cocos-review.md 示例 --- description: 对当前 TypeScript 文件进行 Cocos Creator 规范审查 --- 请审查 $SELECTION 或当前打开文件，检查以下问题并输出清单： 1. @ccclass 和 @property 装饰器是否正确使用 2. 生命周期函数（onLoad/start/update/onDestroy）是否符合规范 3. onDestroy 是否解绑了所有事件监听器 4. 是否有 find() 字符串查找（应改为 @property 引用） 5. update() 中是否有资源加载或 instantiate 调用 6. 跨组件通信是否使用了 EventTarget 单例 输出格式：✅ 通过 / ⚠️ 建议 / ❌ 必须修复

制定 AI 代码 Code Review 标准
AI 产物审查要点 · 必须人工复核的场景
Tech Lead 主导 Design Lead 参与 全员遵守
›
  • AI 生成代码必须在本地 Cocos Editor 中打开、无报错才能提 PR
  • 以下场景必须人工审查，不接受直接合并 AI 产物：数据持久化逻辑、付费/道具结算、权限检查
  • PR 描述中必须注明「AI 生成比例」和「已验证项目」（如已验证：编辑器无报错、场景引用完整）
  • 将 Review checklist 写入 .github/PULL_REQUEST_TEMPLATE.md
